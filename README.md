# reading-capture

本を読みながら、ページの写真とメモを手間なく記録するための Android アプリ（個人用）。

最終更新: 2026-11-21

## 機能

- **撮影**: スマホを手に持ち、カメラをページに向けて静止すると、シャッターを押さなくても自動で撮影する。1 回に 1 ページ。撮影が完了すると短いバイブレーション（0.04 秒）が 1 回鳴る（種類は設定で変更できる）。ページをめくって次のページに向けると、また撮影する。ページ番号が読めたページは重複して撮影しない。シャッターボタンと音量ボタンでも撮影できる。写真はトリミングせずフレーム全体を保存する（長辺 3072px）
- **警告**: 文字が画像の端で見切れている・ブレている・暗すぎるときは、短いバイブレーション 2 回と画面の表示で警告する。「撮り直す」を押すと、その写真を削除し、構え直して静止したところで再撮影する。バイブレーションは、端末の「タッチ操作のバイブレーション」がオフでも、マナーモードでも鳴る
- **アップロード**: 写真とメモを、本人だけが閲覧できる非公開の GitHub リポジトリ（インボックス）にアップロードする。オフライン時は端末に保存し、接続が回復したら自動でアップロードする。アップロードの完了を確認するまで、端末から削除しない
- **本と章・節**: インボックスに登録された本の一覧と目次を読み込み、本を切り替えられる。アプリ自身はインターネットから目次を取得しない
- **メモ**: 入力欄に音声入力したテキストを、選択した本・章・節と日時を付けて、そのまま保存する。音声認識はアプリに実装せず、端末の音声入力（キーボード）を使う
- **共有からの追加**: 他のアプリの「共有」から画像を受け取り、選択中の本の写真としてアップロードする

## アーキテクチャ

Kotlin と Jetpack Compose。モジュールは 2 つ。

| モジュール | 内容 |
| --- | --- |
| `core` | カメラにも Android にも依存しないロジック。静止の検出、ページ番号の選択、文字ブロックの範囲の検出（記録用）、見切れ・ブレ・露出の判定、インボックスのディレクトリ構成、GitHub へのアップロード、目次。Mac 上でユニットテストできる |
| `app` | Android アプリ。カメラ（CameraX）、写真の後処理、端末内の DB、アップロードの制御、UI |

### 自動撮影のロジック

スマホは手に持って使う。同じページでも、位置・大きさ・傾きが毎回変わる。

1. 静止の検出（0.35 秒）。端末の動きはジャイロセンサーで、被写体の動きはフレーム間の差分で判定する。カメラ映像は静止していても細かく揺れるので、ピクセル単位ではなくブロックの平均で比較し、直近のフレームの中央値で判定する
2. 静止したら、フレームの上下の帯領域だけをオンデバイス OCR（ML Kit）で読み、ページ番号を探す。OCR の所要時間はテキスト量にほぼ比例するので、帯領域だけなら速い（実機で 0.15〜0.86 秒。ページ全体を読むと 0.5〜1.5 秒）
3. OCR の間はフレームが届かない。その間にジャイロが 0.2 rad/s を超えていたら、読み取り結果を捨てて静止を待ち直す
4. 未撮影のページ番号なら撮影する。撮影済みの番号なら撮影しない
5. ページ番号が読み取れなければ、帯に文字があれば撮影する。ただし、前回の撮影から端末が動いていないとき（影が通った、手が入った）は、同じページとみなして撮影しない
6. 撮影後は、大きな動き（ページをめくる、別のページへ移動する）があるまで撮影しない。撮影中と撮影後 0.6 秒は、映像の変化を動きに数えず、ジャイロだけで判定する（写真を撮る処理で判定用の映像が乱れるため）

同じページかどうかは、ページ番号だけで判定する。本文のテキストは照合しない。以前は、連続する 3 文字の組のハッシュ値で照合し、一致した写真を破棄していた。1 ページずつ撮影すると隣のページの行が写り込むため、新しい右ページを、直前の左ページと同じと誤判定して破棄した（34 ページ中 8 枚）。番号の読めないページを重複して撮影することはあるが、撮影できた写真は破棄しない。

ページ番号は、撮影前に映像から読めた番号を優先する。撮影後の写真から読んだ番号は、撮影前に読めなかったときだけ使う（実機で、写真からの読み取りが 44→4、47→41 のように 4 件違っていた）。

撮影した写真がブレていたら、そのページ番号を「撮影済み」から外す。向け直せば撮り直される（同じ番号で繰り返すのは 1 回まで）。

OCR で読み取ったテキストは、番号・文字数・行のバウンディングボックスに変換した時点で破棄する。テキストのままでは保持・保存・送信しない。

文字ブロックの範囲の検出（`TextBlockFinder`）は、ページがフレームに収まっているかを判定するための部品。OCR を使わず、明暗の細かさから本文の範囲を求める。現在は数値を記録するだけで、撮影の条件には使っていない。実機の記録を見て、しきい値を決めてから使う。

### 撮影後の検査

撮影した写真は、正しい向きに回転して保存したあと検査する。見切れは、OCR で行のバウンディングボックスだけを取り出して判定する。1 ページずつ撮影すると、隣のページの文字が画像の左右の端に写り込む。ノド（綴じ目）の近くは紙が湾曲していて本文との間隔が詰まって見え、隣のページの小さな文字も写るので、間隔や文字サイズだけでは区別できない。左右の端については、端にかかった行が本文の幅に近い長さのとき（本文の見切れ）と、ページの外側（ページ番号がある側）の端に本文より小さい文字の行が複数続くとき（欄外の注の見切れ）だけ警告する。外側が判別できないときは、注の見切れは警告しない。

ページ番号が読み取れた写真は、インボックスでのファイル名に番号を付ける（`…-cam-p47.jpg`）。

### アップロードのロジック

GitHub の Git Database API（blob → tree → commit → ref）で、写真とメモをまとめて 1 コミットで追加する。

- blob の SHA は内容から決まるので、再アップロードしても重複しない
- 追加する前にインボックスの現在の内容を確認し、同じものがあれば何もしない（成功したのにレスポンスを受け取れなかった場合にリトライしても、重複しない）
- ブランチを強制更新しない。他から先に push されていた場合は、その上に積み直す
- GitHub は書き込み直後の読み取りに古い内容を返すことがある。自分が更新する前の HEAD が返ってきた場合は、反映されるまで待つ
- アクセストークン（fine-grained personal access token）は、Android Keystore で暗号化して端末内に保存する。必要な権限は、インボックス 1 リポジトリに対する Contents の Read and write だけ

インボックスのディレクトリ構成は `core/src/main/kotlin/app/readingcapture/core/inbox/InboxLayout.kt` にある。

### デザイン

白・黒・グレーを基調に、アクセントカラーは青 1 色。警告だけ別の色。ライトモードとダークモードの両方に対応する。モックは `docs/design/mockup.html`（文言は初期のもの。現在の文言はアプリが正）。

## セットアップ

必要なもの: JDK 17、Android SDK（platform-tools、platforms;android-37.1、build-tools;36.0.0）。Android Studio は不要。

`local.properties`（リポジトリにはコミットしない）に、SDK のパスと、インボックスのリポジトリ名のデフォルト値を書く。

```properties
sdk.dir=/path/to/android-sdk
inbox.repo=<owner>/<インボックスのリポジトリ>
```

```sh
export JAVA_HOME=/path/to/jdk17

./gradlew :app:assembleDebug        # ビルド。app/build/outputs/apk/debug/app-debug.apk が生成される
adb install -r app/build/outputs/apk/debug/app-debug.apk   # USB で接続した端末にインストール
```

`scripts/install.sh` は、ビルドから、USB で接続した端末へのインストールまでを 1 回で行う。

adb でインストールするアプリは、Android のデベロッパー認証の対象外（<https://developer.android.com/developer-verification/guides/faq>、2026-11-20 に確認）。

## テスト

```sh
./gradlew :core:test                      # Mac 上で実行。合成した映像と画像でロジックを検証する
./gradlew :app:connectedDebugAndroidTest  # エミュレーターか実機で実行。DB の状態遷移と、OCR を使う処理
```

- `core` のテストは、ランダムな文字を並べた合成ページを使う。実際の本のページは使わない。手持ちの揺れ、端末の動き、ページ番号の読み落としと所要時間、OCR 中の端末の動き、撮影時の映像の乱れ、明るさの変化、手や指の写り込み、影、ページをめくりかけて戻す動き、フォーカスの揺れ、バイブレーションによる揺れを、スクリプト化した映像で再生する
- 見切れの判定は、実機で誤検出したときの行の配置（座標の数値）をテストケースにしてある
- `scripts/make-sample-video.sh` で、エミュレーターのカメラに表示する合成ページの映像を `core/build/samples/pages-portrait.mp4` に生成する。エミュレーターは `-camera-back videofile:<動画の絶対パス>` で動画をカメラ映像にできる（動画が無いと、カメラ映像は紫一色になる）
- 環境変数 `INBOX_LIVE_REPO` と `INBOX_LIVE_TOKEN` を渡して `--tests '*LiveGitHubTest*'` を実行すると、実際の GitHub に対してアップロード処理を検証する（ランダムなデータを `selftest/` に追加して削除する）

## チューニング

検出の数値を、端末内の `files/diag/<年-月-日>.jsonl` に 1 行 1 件で記録している（数値だけで、写真の内容やテキストは含まない）。

```sh
adb exec-out run-as app.readingcapture cat files/diag/2026-11-21.jsonl
```

`scripts/pull-diag.sh [年-月-日]` は、ログを取得して、撮影回数・写真ごとのシャープネスと警告・写真のサイズ・アップロード処理のサマリーを表示する。

撮り逃しや重複撮影が起きたときの数値を見て、`core` の `EngineConfig` / `QualityConfig` のしきい値を調整する。設定画面で、数値を撮影画面に表示することもできる。
